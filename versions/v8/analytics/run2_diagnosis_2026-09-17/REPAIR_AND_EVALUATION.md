# Исправление oracle и оценка игры против пула

Это проект исправления с CPU-прототипом, не внесённый production patch. Исходные `env/`, `oracle/`, pipeline и конфигурация не менялись.

## Минимальное исправление CV

Точная freeze-equity baseline B(s) имеет мартингальное свойство при открытии карты и фиксированных live/bets:

\[
\mathbb E[B(S')\mid s]=B(s).
\]

Пусть b(s;U) — среднее по M равномерным завершениям борда, где U — вспомогательная случайность, независимая от реальных карт и действий rollout. Тогда `E_U b(s;U)=B(s)`. Поэтому:

\[
\mathbb E_{U,S'}[b(S';U)-b(s;U)\mid s]
=\mathbb E_{S'}B(S')-B(s)=0.
\]

Независимость оценок до и после улицы друг от друга не требуется; нужна их несмещённость и независимость вспомогательной случайности от игровой траектории. Политика не должна читать вспомогательные оценки. При fold-коррекции уже используется известная вероятность действия, поэтому её условное среднее по действию равно нулю даже для произвольной фиксированной baseline.

Изменения для production:

1. Передать отдельный `runout_seed` по `HandSpec` → driver → `HandRunout`. В oracle породить независимые потоки игровой и вспомогательной случайности из seed запроса метки. Вспомогательный seed должен обновляться на каждом внешнем sample и при независимом повторе метки.
2. Все альтернативные действия одного sample получают один `runout_seed`. Так сохраняются общие случайные числа и экономия на ранжировании. Разные samples получают разные draws даже при одинаковых hole cards и видимом борде.
3. Включить `runout_seed` в ключ кеша. В seed нельзя включать будущий борд, полный deck или результат игры. Использовать индекс батча/worker как источник seed тоже нельзя: ответ должен сохраняться при смене разбиения работы.
4. Сохранить точное перечисление завершений, когда оно дешевле заданного M. Для turn можно отдельно всегда перечислять оставшиеся риверы, но это улучшение дисперсии/стоимости, а не замена исправления ранних улиц.
5. Версионировать оценщик Q отдельно от модели диапазонов, записывать версию в manifests и проверять при resume. Старые Q автоматически не исправляются. Незавершённую разметку разных версий нельзя смешивать; старые файлы следует сохранить отдельно.

Несмещённость здесь относится к дополнительной CV-коррекции относительно исходного rollout. Это не устраняет остальные аппроксимации oracle, например likelihood floor.

Быстрый диагностический обход — `oracle.control_variate=false` с **новыми** метками. Он убирает данный дефект и повышает дисперсию. Повторное чтение существующих shards с новой настройкой не пересчитывает их Q.

### CPU-проверка прототипа

[fresh_cv_probe.py](/Users/zer0o0ne/Documents/ContinuousLearning/versions/v8/analytics/run2_diagnosis_2026-09-17/fresh_cv_probe.py) использует существующие `_label_plan`, driver и `_label_q`; переопределяет только создание `HandRunout` и его вспомогательный RNG/ключ кеша. Файлы production не патчатся даже временно.

На прежнем контрпримере истинный Q(call) = −127.272727 BB:

| S | Старый CV | Новый случайный CV, seed 7 |
|---:|---:|---:|
| 128 | −175 | −123.632813 |
| 1024 | −175 | −126.562500 |

Это два отдельных численных примера, не доказательство монотонной точности по S. На 32 независимых метках при S=128 среднее −128.2043, SD=3.2779 BB. На 8 метках при S=1024 среднее −127.2491, SD=0.9390 BB. Для фиксированной руки, p(win)=8/44 и M=16 теоретическое SD равно:

\[
400\sqrt{p(1-p)/(SM)}:
\quad 3.4091\ {\rm BB}\ (S=128),\quad1.2053\ {\rm BB}\ (S=1024).
\]

Отдельная точная проверка использует конечный вспомогательный sampler: 16 риверов задаются циклическим окном с равномерным начальным смещением среди 44. Каждая позиция окна имеет равномерный marginal. Полный перебор 44 настоящих риверов × 44 вспомогательных смещений подтверждает правильное среднее с ошибкой 1.42e−14 BB для all-in и обычного turn→river. Этот тест проверяет тождество ожиданий без статистического допуска; IID NumPy sampler проверяется отдельными численными запусками выше.

Для batch sizes 1, 7 и 4096 получен одинаковый Q. Production-реализация дополнительно требует проверки переноса seed через parallel workers, resume, нескольких улиц, multiway и side pots. Производительность на GPU не проверялась.

## Измерять нужно ожидаемый результат полной политики

Зафиксировать распределение соперников μ и режим c (cold либо warm с явно заданной историей/длиной сессии):

\[
V_c(\pi;\mu)=100\sum_j\mu_j\,
\mathbb E[R(\pi,\sigma_j;c)]\quad {\rm BB/100}.
\]

Никакого деления на банк. Все решения hero принимает оцениваемый checkpoint. Для warm весь fit/update проходит по истории именно этой политики. Объектом измерения является фактическая политика вместе с её механизмом адаптации.

Нужны два результата:

- абсолютный `V` против фиксированного набора соперников, с результатом по каждому члену;
- парная разница `Δ=V(new)−V(old)` на одной и той же смеси — для решения о качестве обновления.

Статический anchor pool даёт сравнимую кривую по итерациям. На расширяющемся training pool обе сравниваемые политики нужно оценивать против одной текущей смеси; абсолютные числа разных итераций с разными μ не сравнивать как изменение силы. Высокий V против любого данного пула сам по себе не является оценкой exploitability или гарантией игры против Slumbot.

## Почему число 2000 само по себе ничего не гарантирует

Для N независимых раздач с SD результата σ BB приблизительная 95%-полуширина интервала:

\[
h=1.96\frac{100\sigma}{\sqrt N}\quad {\rm BB/100}.
\]

| Условное σ, BB/hand | h при N=2000, BB/100 | N для h=10 BB/100 |
|---:|---:|---:|
| 10 | 43.83 | 38 416 |
| 20 | 87.65 | 153 664 |
| 50 | 219.13 | 960 400 |

Это арифметические сценарии, не измеренная дисперсия текущего агента. Для h=10 и N=2000 нужно остаточное SD не больше **2.2817 BB**. Без настоящего пилота с checkpoint обещать это нельзя.

## Практическая оценка: парные блоки + исправленный CV

Для каждого независимого блока b выбрать оппонента, колоду и потоки случайности. В HU сыграть обе стороны с перестановкой политик по местам на той же физической раздаче (duplicate), затем повторить блок для старого и нового checkpoint. Вероятности действий могут различаться; общими должны быть равномерные случайные числа, не принудительно выбранные действия.

Пусть Z_new,b и Z_old,b — средние скорректированные выигрыши каждого агента по двум сторонам. Определить:

\[
D_b=Z_{new,b}-Z_{old,b},\qquad
\widehat\Delta=100\bar D,
\quad SE(\widehat\Delta)=100s_D/\sqrt B.
\]

Статистическая единица — независимый блок. Две стороны duplicate или несколько ветвей одной раздачи нельзя объявлять независимыми наблюдениями. Измерять улучшение обычно дешевле, чем абсолютный V, потому что:

\[
\operatorname{Var}(D)=\operatorname{Var}(Z_{new})+
\operatorname{Var}(Z_{old})-2\operatorname{Cov}(Z_{new},Z_{old}).
\]

Общие карты и RNG могут повысить covariance. Это не гарантированная величина: политики могут расходиться по веткам. После исправления можно применять текущую card/fold-CV; её эффективность тоже измеряется, а не предполагается.

### Более сильный оценщик с известными стратегиями пула

У всех игроков известны вероятности действий, поэтому можно делать коррекцию каждого стохастического решения:

\[
Z=R+\sum_t\left[\sum_a p_t(a)h_t(a)-h_t(A_t)\right].
\]

Если весь вектор h_t доступен до выбора A_t и не зависит от будущего исхода, каждый член имеет нулевое условное среднее **даже при неточном h**. Это принцип [MIVAT/AIVAT](https://poker.cs.ualberta.ca/publications/aaai17ws-burch-aivat.pdf). Оценщик продолжает измерять реальный выигрыш, а не качество своего предиктора. Для chance nodes аналогично нужна настоящая условная средняя величина; именно её прежний CV подменял отдельно вычисленной baseline.

Близкое к Q продолжения h может сильно уменьшить дисперсию. Но вызов полного oracle на каждом действии дорог. Начать следует с существующей исправленной card/fold-CV и парных блоков. Дополнительный value-предиктор или более полная AIVAT-коррекция оправданы только после измерения остаточного SD и цены прямого evaluation. Одно использование обученного value-head вместо R не будет несмещённой оценкой V.

## Почему много rollout на 1000 исходных позиций не заменяют охват

Пусть X — выбранные стартовые условия, v(X)=E[R|X], внутри каждого X проведено M независимых продолжений. Тогда:

\[
\operatorname{Var}(\widehat V/100)
=\frac{\operatorname{Var}_X v(X)}N
+\frac{\mathbb E_X\operatorname{Var}(R|X)}{NM}.
\]

M уменьшает только второй член. Чтобы уменьшить первый, нужны новые исходные раздачи, удачное стратифицирование/duplicate либо корректная коррекция начальной карточной случайности. Поэтому нельзя считать NM независимыми раздачами, если имеется всего N повторяемых исходных позиций.

## Достаточно конкретный порядок запуска

1. На исправленном оценщике взять независимый пилот порядка 1000–2000 парных блоков. Печатать raw/CV absolute V, paired Δ, SD блока, SE, число блоков и wall-clock. Разложить по соперникам. Пилот — измерение дисперсии и стоимости, не сертификат силы.
2. Заранее выбрать требуемую полуширину h. По SD пилота назначить размер отдельной основной выборки `B≈(1.96·100·s_D/h)^2` с запасом на оценку SD. Проводить её на новых seeds, общих для сравниваемых политик.
3. При стратификации по соперникам оценивать `V=100·Σ μ_j mean_j`, `SE²=100²·Σ μ_j²·s_j²/B_j`. При одинаковой цене блока распределение `B_j ∝ μ_j s_j` уменьшает дисперсию. Веса самой метрики μ при этом остаются фиксированными.
4. Для warm использовать независимые сессии или иное корректное блокирование. Из-за адаптации последовательные руки не являются IID; SE по числу рук без учёта этого будет занижен. Cold измерять отдельно.
5. Не останавливаться на первом положительном обычном 95%-интервале. Либо фиксировать размер основной выборки после независимого пилота, либо использовать специально построенный последовательный confidence sequence.

Количество rollout/forward при разметке существенно больше количества действий в обычных матчах. Поэтому большой прямой evaluation может оказаться дешевле добавления сложного оценщика. Это нужно проверить wall-clock пилота на машине обучения; измерений времени нового evaluator с текущими весами здесь нет.

Сначала исправление Q, затем этот pilot. Положительный normalized `ev_agent` оставить только как явно обозначенную вспомогательную метрику; решение о продолжении обучения принимать по результату полной политики и парной разнице с неопределённостью.
